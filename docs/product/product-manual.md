# 软件产品说明书

> 产品：设备检修知识检索与作业辅助系统
> 版本：v0.1.0
> 日期：2026-05-21

## 1. 产品概述

### 1.1 产品定位

设备检修知识检索与作业辅助系统（Maintenance Copilot）是一款面向工业、能源、制造等领域一线检修场景的智能化知识工作台。系统以多模态大模型技术为核心，整合检修手册、历史案例和标准化作业流程，帮助检修人员更快查找资料、规范作业、沉淀经验。

### 1.2 目标用户

- **一线检修人员**：日常故障排查、查阅检修流程、提交维修记录
- **知识管理员**：审核维修案例、管理知识资料、优化知识库质量
- **企业管理层**：了解设备维护状况、评估检修效率

### 1.3 核心价值

| 痛点 | 解决方案 | 价值 |
|------|----------|------|
| 知识分散、检索困难 | 统一知识检索入口，手册/案例/资料一键搜索 | 减少查找时间 50%+ |
| 新人上手慢、经验断层 | 历史案例沉淀复用，标准化流程指引 | 缩短新人培训周期 |
| 作业不规范、安全隐患 | 步骤化操作指引 + 安全提醒 + 验收标准 | 降低操作失误率 |
| 经验难以传承 | 案例提交审核机制，知识持续沉淀 | 形成数字化知识资产 |

## 2. 功能说明

### 2.1 知识检索

在检索输入区填写设备型号和故障现象，点击「开始检索」，系统自动搜索检修手册、历史案例和入库资料，返回按相关性排序的结果列表。

每条结果展示：
- **标题**：知识条目名称
- **来源标签**：手册 / 案例 / 资料
- **来源信息**：来源名称、章节、页码
- **内容摘要**：关键内容片段
- **命中原因**：具体命中了哪些检索词
- **排序分和置信度**：量化检索匹配程度

### 2.2 标准化作业指引

点击检索结果中的任意一条，系统自动展示关联的标准化作业流程。

流程包含：
- **基本信息**：设备类型、故障类型、检修等级
- **所需工具**：维修需要用到的工具和仪器
- **操作步骤**：按顺序排列的步骤，每步有标题、详细描述和安全警告
- **安全提醒**：作业过程中的安全注意事项
- **验收标准**：完成后的检查项

### 2.3 维修案例提交与审核

**提交案例**：在「经验案例提交」面板填写：
- 可能原因：导致故障的推测原因
- 处理方案：具体的维修操作
- 处理结果：维修后的效果
- 标签：分类关键词，便于后续检索

提交后案例进入审核队列，状态为「待审核」。

**审核案例**：在「案例审核」面板点击「刷新」查看待审核案例，点击「通过」入库或「拒绝」退回。审核通过后，新案例可被检索命中，实现经验复用。

### 2.4 资料入库管理

在「资料入库」面板上传 PDF、TXT 或 Markdown 格式的检修资料。系统自动：
1. 校验文件格式和大小
2. 提取文本内容（PDF 通过 pypdf 解析）
3. 按 700 字分块并提取关键词
4. 存入知识库

入库后的资料列表展示文件名、解析状态、片段数量和上传时间。入库资料可被检索，也可随时删除。

### 2.5 RAG 辅助诊断建议

点击「生成辅助建议」，系统基于当前检索结果构建上下文，通过大语言模型生成带引用的诊断建议。

输出内容包括：
- **诊断回答**：结合检索资料的综合分析
- **建议动作**：推荐的排查和修复步骤
- **引用来源**：每条建议引用了哪些知识条目

不配置大模型 API 密钥时，系统自动使用内置 Mock 模式生成建议，功能不受影响。

### 2.6 现场材料上传

支持上传故障现场图片（JPG/PNG/WebP）或 PDF 报告，上传后返回文件 ID 和访问地址。上传过程包含格式、大小和内容校验。

## 3. 界面展示

### 3.1 整体布局

系统采用工业控制台风格的深色顶部 + 浅色工作区设计。界面分为以下区域：

- **顶部横幅**：系统标题、状态芯片（可解释检索 / Mock 降级模式 / 本地知识库）、核心指标概览
- **左侧**：检索输入区
- **中部**：知识结果区
- **右侧**：作业指导区
- **底部**：资料入库、RAG 辅助建议、案例提交、案例审核面板

### 3.2 界面特点

- **卡片式布局**：每个功能区域为独立圆角卡片，边界清晰
- **来源标签**：不同知识来源用不同颜色标签区分（橙色 = 手册 / 案例 / 资料）
- **状态提示**：加载状态、空状态、错误状态均有明确提示文案
- **响应式设计**：小屏幕自动切换为单列布局
- **无障碍支持**：键盘焦点样式、动画降级适配

## 4. 操作指南

### 4.1 典型操作流程

**场景：发动机启动困难故障排查**

1. 打开系统，在检索输入区填写：
   - 设备型号：`发动机-示例型号 A`
   - 故障现象：`启动困难，怠速不稳，排气异常`
2. 点击「开始检索」，查看检索结果列表
3. 点击第一条结果「发动机启动困难检查流程」，查看作业步骤
4. 按步骤操作后，在「经验案例提交」面板填写维修信息：
   - 可能原因：`火花塞积碳`
   - 处理方案：`清理并更换火花塞，复查燃油滤清器`
   - 处理结果：`启动恢复正常，怠速稳定`
   - 标签：`启动困难, 点火系统, 火花塞`
5. 点击「提交审核」
6. 在「案例审核」面板点击「刷新」，找到刚提交的案例，点击「通过」
7. 重新点击「开始检索」，确认新案例出现在结果中

**场景：上传检修资料并检索**

1. 在「资料入库」面板填入资料来源名称（如"摩托车检修手册"）
2. 选择 PDF 文件上传
3. 查看入库状态（已入库 / 片段数 / 解析器）
4. 在检索区输入相关设备型号和故障描述
5. 点击「开始检索」，确认入库资料片段出现在结果中

**场景：获取 RAG 辅助建议**

1. 完成知识检索
2. 点击「RAG 辅助建议」面板的「生成辅助建议」
3. 查看生成的中文诊断建议和引用的知识来源
4. 注意 Provider 标签：绿色 = 真实模型，橙色 = Mock 降级

### 4.2 常见问题

**Q: 检索没有结果？**
A: 检查设备型号和故障现象是否填写。可尝试使用更通用的关键词，或先上传相关的检修资料。

**Q: 上传资料失败？**
A: 确认文件格式为 PDF/TXT/MD，大小不超过 20MB。PDF 文件需要是文字型（非扫描件），扫描件需要二阶段 OCR 支持。

**Q: RAG 建议显示"Mock 降级"？**
A: 表示当前未配置大模型 API Key。在 `.env` 文件中配置 `OPENAI_API_KEY` 或 `ANTHROPIC_API_KEY` 即可接入真实模型。Mock 模式下建议同样基于检索结果生成，只是回答模板化。

**Q: 案例审核后检索不到？**
A: 确认审核时选择了「通过」而非「拒绝」。只有 approved 状态的案例才能被检索。

## 5. 技术特性

| 特性 | 说明 |
|------|------|
| 可解释检索 | 每条结果标注命中词、来源位置和排序分，让用户理解为什么返回这个结果 |
| 模型降级保障 | 未配置 API Key 或网络异常时自动回退到本地 Mock，核心功能不受影响 |
| 零外部依赖运行 | 仅需 Python + Node.js，不配置任何云服务即可完成检索、流程和案例管理 |
| 国产化适配 | 面向 LoongArch + 银河麒麟，使用纯 Python PDF 解析器，不依赖 x86 原生库 |
| 轻量可扩展 | MVP 阶段 JSON 文件存储，二阶段可平滑升级到向量数据库和关系型数据库 |
