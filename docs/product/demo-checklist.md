# 端到端演示检查清单

本文档用于 3 到 5 分钟比赛演示。目标是稳定展示“资料入库 -> pending_review 可见/片段修正 -> 已审核知识检索 -> RAG 引用回答 -> 作业流程 -> 案例沉淀”的闭环。

## 1. 演示前检查

1. 在仓库根目录运行 `dev start`。
2. 运行 `dev verify` 确认后端和前端都可访问。
3. 打开 `http://127.0.0.1:5173/`。
4. 后端健康检查访问 `http://127.0.0.1:8000/api/health`。
5. 如需命令验证，运行 `powershell -ExecutionPolicy Bypass -File .\scripts\run-backend-tests.ps1`。
6. 准备一份小于 20MB 的 `md` 或 `txt` 检修资料，内容建议包含“摩托车发动机无法启动、火花塞、高压包、燃油供给”等关键词。

## 2. 固定演示输入

设备型号：

```text
发动机-示例型号 A
```

故障现象：

```text
启动困难，怠速不稳，排气异常
```

资料入库示例文本：

```text
摩托车发动机无法启动时，应检查火花塞、高压包和燃油供给。若怠速不稳，应检查进气管路密封和怠速控制部件。
```

案例提交：

```text
原因：火花塞积碳
方案：清理并更换火花塞，复查燃油滤清器。
结果：启动恢复正常，怠速稳定。
标签：启动困难, 点火系统, 火花塞
```

## 3. 演示步骤

1. 展示首页工业控制台和默认检索输入。
2. 在“资料入库”上传示例资料，确认状态为“待审核”并显示 chunk 数量。
3. 打开片段修正入口，展示 pending_review 片段可查看、可人工修正并生成 revision；不要宣称当前已有资料片段 approve/reject 工作台。
4. 点击“开始检索”，展示已审核手册、案例或已审核资料结果，并说明结果带来源和命中原因。
5. 点击“生成辅助建议”，展示 Mock RAG 回答、建议动作和引用来源。
6. 点击有关联流程的检索结果，展示工具清单、安全提醒、作业步骤和验收标准。
7. 上传一份现场图片或 PDF，说明这是多模态入口占位。
8. 提交维修案例，进入待审核。
9. 在审核区域通过案例。
10. 再次检索相关关键词，展示新案例已可被检索。

## 4. 兜底说明

1. 如果真实 LLM Key 未配置，系统使用 mock provider，不影响演示。
2. 如果 PDF 解析器未安装，PDF 资料可能显示 `needs_parser`，演示时优先使用 TXT/Markdown 资料。
3. 如果浏览器插件拦截 localhost，可使用后端测试和前端 build 作为替代验证证据。
4. 如果上传资料未命中，先确认片段是否仍为 `pending_review`；当前演示检索优先使用已审核种子手册/案例。
5. 如果案例审核区为空，先重新提交一条案例再刷新审核列表。
## 5. 官方 PDF 与多模态分析演示补充

官方样例资料位置：

```text
E:/Download/Downloads/摩托车发动机维修手册.pdf
```

演示建议：

1. 先用 TXT/Markdown 资料演示稳定入库、检索、RAG 引用闭环。
2. 再上传官方 PDF 或现场故障图片，说明系统会优先尝试本地文本解析。
3. 当资料状态显示 `待多模态分析` 时，点击“多模态分析”。
4. 无真实 API Key 时系统使用 mock provider，仍会生成摘要、关键部件、故障现象、检查步骤和 `pending_review` 知识片段。
5. 统一资料片段审核入口补齐前，不要演示“一键审核资料片段”；当前只展示 pending_review 片段可见和人工修正。
6. 真实 OpenAI/Anthropic 多模态 API 仅作为增强能力，演示时不要承诺必须联网运行。

风险兜底：

1. 官方 PDF 不进入 Git 仓库。
2. 若真实 API 受网络、费用、页数或文件大小限制影响，使用 mock provider 完成演示。
3. 若官方 LoongArch/银河麒麟环境暂未开放，只展示本地功能闭环和待验证清单。
