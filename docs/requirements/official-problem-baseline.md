## 2. 赛题目标摘要

赛题聚焦工业、能源、制造等领域设备检修中的核心痛点，要求围绕“知识分散、检索低效、作业不规范、经验传承难”等问题，开发一款兼具智能化、实用性与创新性的设备检修知识检索与作业辅助系统。

当时竞赛开发围绕以下业务价值展开；这些价值可供当前产品参考，但不替代现行 SRS：

1. 帮助一线检修人员快速检索检修知识与作业资源。
2. 帮助现场人员规范执行标准化作业流程，降低误操作。
3. 帮助企业把案例、经验和手册沉淀为可持续更新的知识资产。
4. 体现多模态大模型技术与行业场景结合的实际价值，而不是只做通用聊天或普通 CRUD 系统。

## 3. 官方业务场景

官方场景聚焦钢铁、汽车制造等行业的大型企业产线设备检修，核心背景包括：

1. 设备密集且联动性强，设备稳定运行直接影响产能与效益。
2. 检修知识散落在手册、日志和老师傅经验中，形成数据孤岛。
3. 新人上手慢，故障响应效率低。
4. 非计划停机会造成高额损失，迫切需要可落地的智能辅助系统。

允许参赛者围绕制造业核心生产设备检修场景自由选型，本项目当前选择“摩托车发动机检修”作为演示场景，属于赛题允许的合理简化场景。

## 4. 官方功能要求

官方要求的软件为 B/S 架构，并应覆盖以下能力：

1. 支持本地部署大模型服务或云端大模型服务，并提供 PC Web 或 App 可视化界面。
2. 多模态知识检索功能：
   文本、故障图片、设备型号等多类型输入。
   精准语义检索与跨模态匹配。
   快速调取检修手册等资源。
3. 标准化作业指引功能：
   嵌入检修全流程。
   提供步骤化操作指引与合规校验提醒。
   支持根据设备类型与检修等级个性化推送流程。
4. 知识沉淀与更新功能：
   支持上传检修案例、经验总结等内容。
   经审核后纳入知识图谱。
   支持手动标注与修正大模型输出结果。

## 5. 官方非功能要求

1. 界面设计合理、美观大方。
2. 软件开发文档完整规范。
3. 人机交互便捷，适合实际使用。
4. 软件保持易用性与稳定性。

## 6. 官方实现条件与硬约束

这是后续开发最容易漂移、也最需要反复提醒的部分。

1. 软件需部署在 LoongArch 架构 CPU + 银河麒麟高级服务器操作系统 V11/V10 上运行。
2. 官方说明中明确写出：不满足该要求视为 0 分。
3. 大赛由龙芯云平台提供远程开发环境，虚机为 LoongArch 架构。
4. 检修设备、开发语言、技术框架不限。
5. 参考资料中提供《摩托车发动机维修手册.pdf》。

对本项目的直接影响：

1. 对当时 A1 竞赛提交而言，LoongArch + 银河麒麟是竞赛交付约束；当前产品基础交付平台已经按 README 调整为 Windows，Linux 和国产化环境需作为另行定义并重新验证的适配项。
2. 任何新增依赖，尤其是 OCR、向量库、模型服务、原生扩展，必须记录 LoongArch/银河麒麟兼容性风险。
3. 当前 Windows 本地开发闭环只能算开发期便利条件，不能替代最终国产化部署验证。

## 7. 当前项目的对齐与差距

截至 2026-05-21，项目与官方赛题的关系应统一表述如下：

### 已对齐部分

1. 采用 B/S 架构。
2. 已有 PC Web 可视化界面。
3. 已实现“检索 -> 作业流程 -> 案例提交 -> 审核 -> 再检索”的核心业务闭环。
4. 已具备云端模型适配接口与 mock 降级路径。
5. 已具备资料入库、来源引用、人工审核和知识更新雏形。

### 尚未完全对齐部分

1. 多模态能力当前仍以文本检索为主，图片/OCR/跨模态匹配尚未完整落地。
2. “知识图谱”当前应表述为“可审核更新的知识库/知识网络雏形”，不能直接宣称已完成知识图谱。
3. LoongArch + 银河麒麟运行要求目前主要停留在文档和风险跟踪层，尚未形成最终部署证明。
4. 本地大模型服务尚未给出针对 LoongArch 环境的明确可运行方案。

## 8. 后续开发的强制约束

后续所有 agent 与人工开发都必须遵守：

1. 不得把当前“图片上传入口”直接表述为“已完成多模态检索”。
2. 不得把当前“审核后进入检索”直接表述为“已完成知识图谱”。
3. 不得把当前“Windows 本地运行成功”表述为“已满足 LoongArch + 银河麒麟部署要求”。
4. 在比赛作品叙述中，必须明确区分：
   当前已落地能力。
   已设计但未完全实现能力。
   官方硬约束但仍待验证能力。
5. 若后续路线发生偏移，优先回到本文件对照，而不是只参考当前代码状态。

## 9. 当前建议的比赛导向

在不破坏当前稳定演示闭环的前提下，后续开发优先级应围绕以下三条主线纠偏：

1. 补齐最小可证明的多模态能力。
2. 为 LoongArch + 银河麒麟部署要求准备兼容性记录、验证步骤和最终证明材料。
3. 在答辩和文档中用更准确的术语描述“知识库更新”和“知识图谱目标”的关系。
