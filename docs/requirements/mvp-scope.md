本文档定义第一版最小可运行闭环。MVP 阶段只追求“能完整演示核心价值”，不追求所有能力一次到位。

## 1. MVP 目标

三天内完成一条可演示主线：

```text
输入设备型号和故障描述 -> 返回知识检索结果 -> 查看标准作业步骤 -> 提交维修经验案例 -> 审核后进入知识库
```

## 2. MVP 用户角色

| 角色 | 目标 | MVP 中是否实现 |
| --- | --- | --- |
| 一线检修人员 | 快速查找故障处理方案 | 实现 |
| 班组长/审核员 | 审核和修正经验案例 | 简化实现 |
| 系统管理员 | 管理用户和权限 | 暂缓 |
| 知识库维护人员 | 导入手册和知识文档 | 简化实现 |

## 3. MVP 页面

| 页面 | 说明 | 优先级 |
| --- | --- | --- |
| 首页/工作台 | 展示检索入口、常用设备、最近案例 | P0 |
| 知识检索页 | 输入设备、故障现象、文字描述，可上传图片占位 | P0 |
| 检索结果页 | 展示相关手册、案例、模型建议、来源引用 | P0 |
| 作业指导页 | 展示步骤、工具、安全提醒、验收标准 | P0 |
| 案例提交页 | 提交故障现象、处理过程、结果、附件 | P1 |
| 案例审核页 | 审核通过、驳回、补充标签 | P1 |
| 系统设置页 | 模型密钥、用户权限、日志等 | 暂缓 |

## 4. MVP 后端能力

| 能力 | 范围 | 优先级 |
| --- | --- | --- |
| 健康检查 | 返回服务状态 | P0 |
| 知识检索 | 基于样例数据进行关键词匹配 | P0 |
| 故障诊断建议 | 可先使用规则或模拟模型响应 | P0 |
| 作业流程获取 | 根据故障或设备返回固定流程 | P0 |
| 案例提交 | 保存案例并标记待审核 | P1 |
| 案例审核 | 修改案例状态 | P1 |
| 文件上传 | 支持图片或 PDF 保存 | P1 |
| 用户登录 | MVP 可暂缓，演示期可模拟角色 | 暂缓 |

## 5. 暂缓功能

以下功能可以作为后续亮点，但不进入第一版 MVP：

1. 完整权限系统。
2. 真正的知识图谱可视化。
3. 高精度图片识别。
4. 多轮对话记忆。
5. 多租户管理。
6. 移动 App。
7. 复杂流程编排引擎。
8. 自动生成完整维修报告。

## 6. 演示主线

建议第一条演示路线：

1. 检修人员进入系统首页。
2. 输入设备型号：`发动机-示例型号 A`。
3. 输入故障现象：`启动困难，怠速不稳，排气异常`。
4. 系统返回可能原因、相关手册段落、历史案例。
5. 用户点击“查看作业指导”。
6. 系统展示安全检查、工具清单、拆检步骤、复核标准。
7. 用户提交本次维修经验。
8. 审核员进入案例审核页，通过该案例。
9. 再次检索时，该案例出现在知识结果中。

## 7. MVP 验收标准

MVP 完成必须满足：

1. 前后端可以本地启动。
2. 至少有 3 条设备故障样例。
3. 至少有 3 条标准作业流程。
4. 检索结果能展示来源、建议、相关案例。
5. 案例提交和审核流程可以演示。
6. 大模型不可用时，系统仍有稳定降级结果。
7. 文档中记录本地启动步骤。
