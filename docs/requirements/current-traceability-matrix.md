## 1. 使用规则

1. 本矩阵只记录需求到模块、实现资产、验证证据和缺口的当前映射，不重述或改变需求语义。
2. 功能状态只能使用：`未开始`、`已设计`、`代码已搭建`、`单元已验证`、`集成已验证`、`已完成`。
3. “状态对象”必须明确到可独立验证的模块、公共契约或能力边界；不得把部分能力的验证结果外推为整个项目或整组业务需求的完成状态。
4. “实现资产”与“功能状态”分栏记录。历史原型、测试夹具、离线脚本或设计稿只能作为资产，不能单独提升功能状态。
5. 同一行可以合并需求编号，但仅限状态对象、功能状态、证据和未关闭缺口均相同的需求；任一项分化时必须拆行。
6. 功能状态变化原则上只更新本矩阵并新增变更日志。仅当需求语义、验收口径或模块边界改变时，才同步修改 SRS 或设计文档。
7. 具体领域事件以 [领域事件目录](../design/event-catalog.md) 为唯一事实源；本矩阵不复制事件名称和载荷定义。

## 4. 状态升级门禁

- `代码已搭建`：必须能定位当前代码或迁移资产，但可以尚未有足够自动化验证。
- `单元已验证`：必须有当前代码基线上的自动化单元或受控进程级证据，且证据覆盖该状态对象的声明范围。
- `集成已验证`：必须记录真实跨组件依赖、数据库或部署环境、执行命令、结果、基线提交和剩余限制。
- `已完成`：除集成证据外，相关 MUST 需求、迁移、公共契约、生产身份、运维交付和未关闭冲突必须全部闭环。

任何升级都必须在同一逻辑变更单元中新增 `docs/change-log/` 记录并更新 `INDEX.md`；若证据只覆盖子集，应拆分状态对象，不能提高整行或整模块状态。
