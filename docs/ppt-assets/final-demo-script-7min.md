# 7 分钟功能演示脚本

版本日期：2026-06-27

## 0:00-0:30 赛题痛点与系统定位

说明检修资料分散、现场故障信息多源、人工经验难沉淀。本系统定位为“设备检修知识检索与作业辅助系统”，核心是 approved-only 检索、Evidence Pack、RAG 作业指引和审核后知识沉淀。

## 0:30-1:00 LoongArch / Provider 状态

展示首页 Provider 状态：LLM、多模态、OCR、embedding、向量库、MinerU/fallback。说明 LoongArch/Kylin 已有主链路复验记录，offline/mock 可兜底，真实 Qwen 文本 LLM 已验证。

## 1:00-1:50 设备型号 + 故障描述 + 检修等级检索

输入“发动机-示例型号 A”“启动困难，怠速不稳”，选择一般检修。点击开始检索，展示 approved 证据、命中原因、来源、score breakdown 和引用信息。

## 1:50-2:40 故障图片诊断与跨模态线索匹配

上传故障图片。展示 OCR 文本、视觉症状、识别部件、fallback 状态和匹配说明。强调口径：图片经 OCR/多模态转为语义线索，合并到 queryContext，增强 approved-only 检索；不是生产级图文向量检索。

## 2:40-3:40 RAG 作业指引 + 合规校验 + Evidence Pack

点击生成检修建议。展示初步判断、检修等级说明、作业前准备、检查步骤、维修步骤、风险控制、合规校验、安全提醒、验收标准、引用证据和不确定信息。

## 3:40-4:40 案例/经验总结提交

在案例面板填写故障原因、解决方案、处理结果、经验总结、教训复盘和标签。提交后显示 pending_review，说明未审核案例不会进入检索。

## 4:40-5:30 审核 approved 后再检索

进入审核工作台，审核通过案例或知识片段。再次检索，展示 approved 后可以命中并进入 citations。

## 5:30-6:10 RAG 回答标注/修正

在 RAG 面板点击“标注/修正本回答”，填写修正建议、标签和原因。提交后进入 pending_review；审核通过后作为 `rag_feedback` 节点进入轻量知识关系网络。

## 6:10-6:40 知识关系网络

展示查询子图或全局图谱，说明设备、故障、手册、案例、资料、片段、术语、provider、rag_feedback 的可追溯关系。强调这是轻量知识关系网络 / 原型。

## 6:40-7:00 总结与商业价值

总结系统价值：提升检索效率、规范检修流程、降低误操作、沉淀一线经验、支持国产化部署和弱网兜底。
