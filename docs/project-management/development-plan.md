# MVP 后续开发实施计划

> 本计划已纳入 `model-task-classification.md` 的任务分流规则：架构、RAG、模型、多模态、测试策略和答辩材料由高智能模型或团队重点复审；页面占位、mock 数据、基础 API、文档格式和测试骨架可作为普通模型任务执行；参赛信息、最终技术承诺、版权来源和提交材料由团队人工确认。

## 1. 当前基线

当前仓库已经从“文档准备阶段”进入“可运行骨架阶段”：

1. 前端工程已初始化为 Vue 3 + TypeScript + Vite + Element Plus。
2. 后端工程已初始化为 FastAPI。
3. `data/examples/` 已有设备、手册片段、维修案例和作业流程 mock 数据。
4. 本地启动脚本和后端接口测试脚本已补充。
5. 后端接口测试通过，前端生产构建通过。
6. 案例提交、审核和审核后再检索已经形成可验证闭环。
7. 前端工作台已拆分为检索输入、结果列表、作业指导和案例提交组件，并接入图片上传入口。

这些改动仍属于 MVP 骨架，不改变前期确定的轻量 B/S 架构。

## 6. 执行规则

1. 每个阶段先处理重点任务，再批量执行普通任务。
2. 涉及架构、API、数据模型、模型适配、检索排序、上传安全和答辩材料的改动必须复审。
3. 普通模型任务必须给出任务编号、输入文件、输出文件、不要做什么和验收标准。
4. 每完成一个可运行小闭环，就同步更新接口文档、测试记录和演示脚本。
5. MVP 完成前不扩展完整权限系统、知识图谱、高精度图片识别、多租户或自动报告生成。
