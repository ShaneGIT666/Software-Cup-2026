# 模型能力分级与任务分类

本文档用于把后续任务按“需要高智能模型重点处理”和“普通模型即可处理”进行分流。目标是把高智能模型用在真正需要架构判断、复杂推理、核心算法和质量把关的地方，把普通模型用于模板化、重复性、资料整理和局部实现，降低成本并减少返工。

## 1. 分类原则

| 分类 | 判断标准 | 推荐模型 |
| --- | --- | --- |
| 重点任务 | 涉及架构取舍、跨模块影响、复杂业务理解、RAG/多模态质量、答辩策略、风险判断 | 高智能模型 |
| 普通任务 | 需求明确、边界清晰、可按模板执行、主要是整理/填充/局部编码/格式调整 | 普通模型 |
| 人工确认 | 涉及真实参赛信息、最终技术路线、提交材料、学校/队伍信息、版权和部署承诺 | 团队人工确认 |

使用原则：

1. 先让高智能模型拆任务、定边界、给验收标准。
2. 再让普通模型执行清晰的小任务。
3. 涉及核心链路和比赛评分点的结果，最后再用高智能模型复审。
4. 普通模型产出的代码和文档必须经过人工或高智能模型抽查。

## 2. 需要重点解决的任务

这些任务建议优先调用高智能模型，因为它们决定系统方向、演示质量和后续返工风险。

| 编号 | 任务 | 原因 | 推荐产出 |
| --- | --- | --- | --- |
| KEY-01 | 最终技术栈确认 | 影响前后端、部署、团队协作和国产化适配 | 技术选型决策记录 |
| KEY-02 | MVP 功能边界收敛 | 决定比赛期间做什么、不做什么 | MVP 范围和阶段路线 |
| KEY-03 | 系统总体架构设计 | 涉及前端、后端、数据、模型、检索和部署边界 | 架构图、模块职责、数据流 |
| KEY-04 | RAG 检索方案设计 | 影响知识检索质量、来源引用和大模型可信度 | 检索流程、切分策略、引用策略 |
| KEY-05 | 大模型适配层设计 | 决定是否能切换 Qwen、DeepSeek、Ollama、LiteLLM 等模型 | Provider 接口、降级策略、配置方案 |
| KEY-06 | 多模态能力路线设计 | 图片/OCR/文档解析涉及不确定性和部署风险 | MVP 占位方案、二阶段增强方案 |
| KEY-07 | 核心数据模型设计 | 影响检索、案例沉淀、审核、作业流程 | ER 草案、字段定义、状态流转 |
| KEY-08 | API 契约复审 | 前后端联调成本高，接口错误会反复返工 | OpenAPI 草案、响应规范、错误码 |
| KEY-09 | 演示主线设计 | 直接影响答辩效果和评分感知 | 3 到 5 分钟演示脚本 |
| KEY-10 | 国产化部署风险评估 | LoongArch 和银河麒麟要求是硬约束 | 依赖兼容清单、规避策略 |
| KEY-11 | 关键代码评审 | 涉及检索、模型调用、数据一致性、上传安全 | Review 结论和修复建议 |
| KEY-12 | 测试策略与验收标准 | 决定核心路径是否稳定 | 测试矩阵、验收清单 |
| KEY-13 | 答辩材料逻辑打磨 | 需要把技术、业务价值和创新性讲清楚 | PPT 结构、讲稿、亮点提炼 |
| KEY-14 | 商业可行性与创新点提炼 | 影响评分项中的创新与商业价值 | 价值说明、落地场景、扩展路线 |

## 3. 普通模型即可处理的任务

这些任务边界较清晰，适合交给普通模型批量处理，再由团队或高智能模型抽查。

| 编号 | 任务 | 输入要求 | 验收标准 |
| --- | --- | --- | --- |
| GEN-01 | 根据模板补全文档初稿 | 提供章节标题和已有资料 | 格式正确，无明显空段 |
| GEN-02 | 整理会议纪要 | 提供会议要点 | 形成结论、待办、负责人 |
| GEN-03 | 生成 GitHub Issue 草案 | 提供任务编号和描述 | 标题、目标、验收标准完整 |
| GEN-04 | 编写简单页面占位组件 | 提供页面名称和字段 | 可运行、无复杂业务逻辑 |
| GEN-05 | 编写 mock 数据 | 提供数据模型字段 | JSON 结构合法，覆盖演示场景 |
| GEN-06 | 根据 API 草案生成前端请求封装 | API 契约已稳定 | 类型和路径正确 |
| GEN-07 | 根据 API 草案生成接口测试样例 | API 契约已稳定 | 覆盖成功和常见失败场景 |
| GEN-08 | 补充 README 小节 | 提供明确内容 | 表述准确、链接正确 |
| GEN-09 | 整理样例故障案例 | 提供设备和故障类型 | 字段完整、语言统一 |
| GEN-10 | 生成表格、清单、检查项 | 提供分类和规则 | 不改变既有决策 |
| GEN-11 | 修正文档格式 | 提供目标文件 | Markdown 表格和标题规范 |
| GEN-12 | 编写基础部署步骤草案 | 技术栈已确认 | 命令顺序清晰，可人工验证 |
| GEN-13 | 生成演示视频拍摄清单 | 演示脚本已确认 | 镜头、操作、旁白对应 |
| GEN-14 | 编写普通单元测试骨架 | 代码结构已稳定 | 测试可运行，覆盖明确函数 |
| GEN-15 | 翻译或润色非核心文案 | 原文已确认 | 不改变事实和承诺 |

## 4. 按阶段分流

### 阶段 0：开发前准备

重点任务：

1. 技术栈确认。
2. MVP 边界确认。
3. 架构和数据模型确认。
4. 样例设备和故障场景选择。
5. 国产化部署风险初判。

普通任务：

1. 整理启动会纪要。
2. 把任务拆成 Issue。
3. 补齐文档模板。
4. 整理样例资料目录。
5. 生成检查清单。

### 阶段 1：最小可运行闭环

重点任务：

1. 后端模块边界和 API 复审。
2. 检索结果结构设计。
3. 模型降级策略设计。
4. 演示主线稳定性复审。

普通任务：

1. 初始化前端工程。
2. 初始化后端工程。
3. 编写基础页面。
4. 编写 mock 数据。
5. 编写基础 API 路由。
6. 编写本地启动说明。

### 阶段 2：核心能力增强

重点任务：

1. RAG 切分、召回、引用和排序策略。
2. 图片/OCR/多模态接入方案。
3. 大模型提示词与输出约束设计。
4. 知识沉淀审核流设计。
5. 关键代码和安全风险评审。

普通任务：

1. 批量录入手册片段。
2. 生成更多故障案例。
3. 补充页面状态。
4. 编写接口测试样例。
5. 整理运行截图和演示素材。

### 阶段 3：交付与答辩

重点任务：

1. PPT 逻辑与答辩叙事。
2. 创新性和商业价值提炼。
3. 最终风险检查。
4. 演示脚本压缩和兜底方案。

普通任务：

1. 整理测试报告。
2. 整理部署文档。
3. 生成提交清单。
4. 生成视频拍摄提纲。
5. 统一文档格式。

## 5. 三人分工下的模型使用建议

| 成员 | 主责 | 高智能模型使用场景 | 普通模型使用场景 |
| --- | --- | --- | --- |
| A 前端与产品体验 | 页面、交互、演示体验 | 页面信息架构、关键流程体验、演示路径复审 | 组件占位、表格页面、表单字段、样式微调 |
| B 后端与模型检索 | API、检索、模型、数据 | RAG、LLM Adapter、数据模型、接口契约、安全评审 | CRUD、mock API、测试样例、数据导入脚本 |
| C 文档测试部署 | 文档、测试、部署、协调 | 答辩逻辑、评分策略、部署风险、测试策略 | 文档初稿、清单整理、会议纪要、格式统一 |

## 6. 任务交接模板

给普通模型的任务要尽量明确，建议使用：

```text
任务编号：
目标：
输入文件：
输出文件：
必须遵守：
不要做：
验收标准：
```

给高智能模型的任务可以强调判断和取舍：

```text
背景：
当前方案：
备选方案：
约束：
希望你判断：
需要输出：
风险点：
```

## 7. 复审规则

以下内容必须由高智能模型或团队成员复审后再合并：

1. 架构设计变更。
2. API 契约变更。
3. 数据模型变更。
4. 模型调用和提示词变更。
5. 检索排序和引用逻辑变更。
6. 上传文件和安全相关逻辑。
7. 部署方式和环境依赖变更。
8. 最终答辩 PPT 和演示脚本。

以下内容普通检查即可：

1. 文档格式修正。
2. 非核心文案润色。
3. mock 数据补充。
4. 页面占位内容。
5. 简单测试样例。
6. 任务看板同步。
