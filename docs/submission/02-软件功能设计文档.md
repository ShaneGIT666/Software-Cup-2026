# 软件功能设计文档

项目名称：设备检修知识检索与作业辅助系统

版本日期：2026-06-27

## 1. 总体设计

系统采用 PC Web + FastAPI 后端的前后端分离结构。前端面向三类用户组织为三个任务区域：检修助手、管理中心和系统状态。后端提供资料入库、解析、审核、检索、RAG、图片诊断、案例回流、回答修正和知识关系图接口。

设计原则：

- 一线检修人员优先看到线性作业链路。
- 管理审核能力集中放在管理中心，不干扰默认首页。
- 模型、OCR、向量、fallback 和 LoongArch/Kylin 状态集中放在系统状态页。
- 所有正式建议默认只使用已审核资料。

## 2. 用户角色

| 角色 | 主要诉求 | 对应区域 |
| --- | --- | --- |
| 一线检修人员 | 快速描述故障、查看依据、生成检修建议、提交经验 | 检修助手 |
| 知识管理员 / 班组长 | 上传资料、审核片段、审核案例和回答修正 | 管理中心 |
| 运维 / 答辩展示人员 | 查看模型服务、OCR、多模态、向量、fallback、部署状态 | 系统状态 |

## 3. 前端信息架构

### 3.1 检修助手

默认首页为“检修助手”，按五步组织：

1. 描述故障：输入设备型号、故障现象、检修等级，可上传现场图片。
2. 查看依据：展示系统从已审核资料、手册和案例中匹配的参考依据。
3. 生成指引：展示标准作业步骤和智能检修建议。
4. 复核修正：对回答进行标注或修正，默认进入待审核。
5. 提交经验：提交现场处理经验，审核通过后沉淀到知识库。

### 3.2 管理中心

管理中心包含：

- 资料入库：上传 PDF、Office、Markdown 和图片资料。
- 待审核内容：审核资料片段、维修案例和回答修正。
- 审核记录：查看审核流水。
- 知识关系图：查看知识沉淀后的轻量图谱。

### 3.3 系统状态

系统状态展示：

- 模型服务状态。
- OCR 和多模态状态。
- 向量检索和本地轻量检索兜底状态。
- MinerU / Chroma / 最近解析 / 最近索引。
- 离线演示模式和真实 LLM 模式说明。
- LoongArch / Kylin 适配说明。
- 初始化配置脚本命令。

## 4. 知识关系图设计

知识关系图定位为轻量知识关系网络原型，用于展示设备、故障、资料、案例、流程、术语和回答修正之间的关系。

前端展示内容：

- 摘要统计：节点总数、关系总数、设备数、故障数、资料数、案例数、流程数、回答修正数。
- 图例：设备、故障、手册、资料、案例、流程、回答修正、术语、模型分析来源。
- SVG 可视化：最多展示 24 个重要节点，按左中右分层。
- 节点详情：点击节点后展示名称、类型、权重、properties 和相关关系。
- 典型关系路径：设备 -> 故障 -> 参考资料 -> 检修建议等。
- 详细列表：保留完整节点和关系列表，放入折叠区。

安全边界：知识关系图仅展示已审核通过的资料、案例和回答修正；待审核和拒绝内容不会进入正式知识关系图。

## 5. 初始化配置设计

系统新增脚本：

- `scripts/init-config.ps1`
- `scripts/init-config.sh`
- `scripts/validate-provider.ps1`
- `scripts/validate-provider.sh`

初始化脚本支持两种模式：

1. 离线演示模式：写入 mock provider 和本地检索兜底配置。
2. 真实 LLM 模式：写入 OpenAI-compatible `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY` 等配置。

脚本要求：

- 写入 `.env` 前备份旧文件。
- 检查 `.gitignore` 是否忽略 `.env`。
- API Key 只脱敏显示。
- 不通过 Web 页面保存密钥。
- 配置完成后通过系统状态页或 `/api/providers/status` 验证。

## 8. 边界说明

当前系统是比赛交付原型，不宣称完整工业图数据库平台或生产级图文向量检索平台。真实 LLM、OCR、多模态、MinerU、Chroma、Qdrant、sqlite-vec 均为可配置增强，目标环境不满足时必须降级，不影响主流程演示。

## P0 补充：PDF 页面视觉资产 fallback 设计

资料入库链路保持 MinerU 优先。PDF/DOCX/PPTX/XLSX 仍先进入 parser_router 和 MinerU adapter；当 PDF 出现 MinerU 超时、MinerU 不可用或 MinerU 返回 0 个图片 assets 时，后端会自动进入 PDF 页面视觉资产 fallback。

fallback 不改变 API 协议。系统会根据 PDF 页数、页面文本、pypdf 可检测到的图片对象和维修关键词选择代表性页面，生成 `source_type=document_asset`、`knowledge_type=pdf_page_visual_asset`、`review_status=pending_review` 的知识片段。片段进入审核工作台，审核通过前不参与正式检索、RAG citation 或向量同步。

该能力用于保障官方维修手册演示闭环，不等同于生产级图像理解。真实 OCR/多模态 provider 可用时仍优先使用真实分析结果。
