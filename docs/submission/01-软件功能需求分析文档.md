# 软件功能需求分析文档

项目名称：设备检修知识检索与作业辅助系统
赛题：第十五届中国软件杯 A 组 A1 基于多模态大模型技术的设备检修知识检索与作业系统
版本日期：2026-06-27

## 1. 项目背景

工业、能源、制造等场景中的设备检修资料分散在手册、现场记录、维修案例和人员经验中。一线人员在故障处置时需要快速定位设备型号、故障现象、检修等级和安全要求对应的知识，普通关键词查询难以同时满足证据追溯、流程规范和经验沉淀。

本项目建设一个 PC Web 可视化系统，通过资料入库、approved-only 检索、RAG 作业指引、多模态图片线索、审核机制和轻量知识关系网络，辅助一线人员完成检修诊断和标准化作业。

## 2. 赛题业务场景

系统面向设备运维、现场检修和技术管理人员。典型场景包括：

1. 输入设备型号、故障描述和检修等级，快速检索维修手册、历史案例和已审核资料。
2. 上传故障图片，通过 OCR / 多模态分析提取图片语义线索，参与检索诊断。
3. 根据 evidence pack 生成结构化检修建议，保留引用证据和不确定信息。
4. 一线人员提交维修案例、经验总结或修正大模型回答，经过审核后沉淀为可追溯知识。

## 3. 用户角色

| 角色 | 主要需求 |
|---|---|
| 一线检修人员 | 查询故障资料、查看作业步骤、上传图片和案例 |
| 技术审核人员 | 审核资料片段、维修案例、RAG 回答修正和人工标注 |
| 运维管理员 | 配置 LLM/OCR/向量 fallback，检查系统状态和部署健康 |
| 答辩/评审人员 | 查看赛题要求覆盖、证据链、国产化部署和能力边界 |

## 4. 功能需求

1. PC Web 可视化界面：展示检索、资料入库、审核、RAG、知识关系网络和系统状态。
2. 多类型输入：支持设备型号、故障描述、检修等级、故障图片、维修资料和案例。
3. 多模态知识检索：故障图片经 OCR / 多模态分析转为 OCR 文本、视觉症状、识别部件和图片线索，和文本查询共同进入 approved-only 检索链路。
4. Evidence Pack：每条证据保留来源、chunk、文档、页码、章节、版本和审核状态。
5. 标准化作业指引：输出初步判断、检修等级说明、作业前准备、检查步骤、维修步骤、风险控制、合规校验、安全提醒、验收标准、引用证据和不确定信息。
6. 知识沉淀：案例、经验总结、资料解析结果、图片分析结果和 RAG 回答修正均默认进入 pending_review。
7. 审核状态机：支持 `draft/pending_review/approved/rejected/deprecated/replaced`，默认检索只使用 approved。
8. 手动标注与修正：支持对 RAG 回答提交修正、标签和原因，审核通过后进入轻量知识关系网络。
9. Provider 状态：展示 LLM、OCR、多模态、embedding、向量库、MinerU 和 fallback 状态。

## 5. 非功能需求

1. 可部署：支持 Windows 开发环境和 LoongArch / 银河麒麟目标环境。
2. 可降级：无 Key、无外网、无 Chroma、无 Qdrant、无 sqlite-vec、无 MinerU、无真实 OCR 时系统仍可运行。
3. 可追溯：检索结果、RAG 引用、审核事件和人工修正均保留来源。
4. 可测试：后端自动化测试、前端构建、readiness、JSON 巡检和 API 冒烟可重复执行。
5. 安全边界：不提交 `.env`、API Key、运行数据、上传资料、视频、截图和压缩包。

## 6. 运行环境需求

| 环境 | 要求 |
|---|---|
| CPU / OS | LoongArch 架构 CPU，银河麒麟高级服务器操作系统 V11/V10 |
| 后端 | Python 3.11，FastAPI，默认 `uvicorn==0.34.0` + `pydantic<2` |
| 前端 | Node 20 可构建 Vue 3 + Element Plus；生产环境可由 FastAPI 静态托管 |
| 容器 | Docker 可用时优先使用 Docker；不可用时使用 Python venv 部署 |
| 模型 | OpenAI-compatible 文本 LLM 可选接入；mock/offline 为兜底 |

## 7. 数据需求

1. 示例设备、手册、流程和案例位于 `data/examples/`。
2. 上传资料、解析结果、知识片段、审核事件、图谱缓存和 RAG feedback 位于运行时 knowledge 目录。
3. 正式知识检索只读取 approved 内容。
4. 外部维修资料和官方 PDF 不进入源码仓库。

## 8. 安全与审核需求

1. 上传资料解析后默认 `pending_review`。
2. RAG feedback 默认 `pending_review`。
3. rejected / deprecated / replaced 不参与检索和知识关系网络。
4. 拒绝审核必须记录原因。
5. 人工修正必须记录 reviewer、review time、before/after 和 revision。

## 9. LoongArch / 银河麒麟硬约束

目标环境是硬交付边界。无法在 LoongArch / 银河麒麟稳定运行的能力只能作为可选增强或后续路线，不能作为主链路承诺。当前默认路线避免 Chroma、Qdrant、sqlite-vec、真实 OCR、真实视觉模型和 MinerU 成为硬依赖。

## 10. 需求优先级

| 优先级 | 内容 |
|---|---|
| P0 | Web 主链路、检索、RAG、审核、fallback、LoongArch 可运行 |
| P1 | 图片诊断语义线索、RAG feedback、知识关系网络、真实 LLM 验证 |
| P2 | MinerU、真实 OCR、多模态 provider、向量数据库增强 |
| P3 | 权限系统、生产级数据库、完整图数据库、生产级图文向量检索 |

## 11. 官方要求对应关系

系统覆盖 PC Web、本地/云端 LLM 接入、多模态输入、检修知识检索、标准化作业指引、知识沉淀更新、审核机制和 LoongArch / 银河麒麟部署要求。对应状态详见 `docs/requirements/official-compliance-matrix-final.md`。

## 12. 风险边界

1. 跨模态匹配为原型级语义线索匹配，不宣称完整生产级图文向量检索。
2. 知识图谱为轻量知识关系网络 / 原型，不宣称完整工业图数据库平台。
3. hash embedding 是 fallback，不宣称为真实语义 embedding。
4. 真实 LLM 已本地验证，但现场更换 Key、base_url 或模型名时必须重新验证。
